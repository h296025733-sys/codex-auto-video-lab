# 带货信息架构：从产品卖点到诚实的下单理由

本文件用于英语与西语短视频的选角度、写口播和配画面。它把授权教程中可复核的思路操作化，但不执行教程里的关注、留言或咨询 CTA，也不把案例中的产品主张带入新项目。

## Commerce bridge

在写 hook、旁白或找 B-roll 前，先完成下面的桥。每一格都要写证据来源；缺失的格子保留为空，不得用生成图或情绪词补成事实。

| 字段 | 要回答的问题 | 可接受证据 | 不能做的事 |
|---|---|---|---|
| `visible_feature` | 产品真实有什么、能看到什么？ | 用户说明、包装/规格、真实素材、已核验资料 | 从相似产品或装饰图推断能力 |
| `target_situation` | 哪类人在什么具体时刻遇到它？ | 用户给定受众、可合理说明的常见场景 | 把“所有人、任何时候”当受众 |
| `lived_friction` | 该时刻已有的麻烦、阻力或愿望是什么？ | 用户输入、非夸张的情境描述 | 制造疾病、危险、羞耻或恐慌 |
| `desired_state` | 使用后希望更省什么、获得什么感受/便利？ | 与已验证 feature 有合理因果关系的收益 | 保证结果、夸大功效或伪造体验 |
| `reason_to_act_now` | 为什么现在值得查看或购买？ | 已核验促销/库存/时效，或当下场景的真实相关性 | 虚构倒计时、稀缺、价格、安全风险或紧迫感 |
| `objection` | 用户最合理的一个疑问是什么？ | 素材或事实能回答的问题 | 为了话术完整而编造答案 |

默认表达链：

`verified feature -> target situation -> lived friction/desire -> truthful relief/gain -> one action`

产品参数只是起点。只有当它能通过证据边界连接到具体生活情境，才升级成 benefit 或购买理由。

## 脚本与画面的共同设计

1. 先选一个主要受众和一个使用时刻，拒绝“所有人都需要”。
2. 只选一个主桥；其他 feature 若不能加强同一理由，降级为屏幕小标签或删除。
3. Hook 优先暴露受众能立刻识别的情境、冲突或可见结果，而不是先念参数表。
4. Proof 句必须与真实证明镜头同现。场景 B-roll 只能说明“谁/何时/为何在意”，不能替代产品能力证明。
5. Benefit 用受众语言表达具体减负、便利、舒适或自我表达；主观感受要写成适用条件，不写成普遍事实。
6. CTA 只要求一个动作。促销、库存、配送、价格和兼容性只有核验后才能进入。

### 观点型二态 hook

教育型、评测型或“纠正常见误区”的片子可用：

`wrong frame -> right frame -> short definition`

- 两态使用相近构图，让观众只比较观点，不重新寻找主体。
- 红叉/绿勾等二元符号只是说明工具，不提供证据。
- 第二态应在前 3–4 秒内成立；随后立即进入产品或问题的具体证明。
- 普通 product-proof 广告不必强行使用该结构。

## 视觉桥与文字时钟

- `chapter_thesis` 跨多个短语保留，回答“本段结论是什么”。
- `speech_caption` 按自然短语更新，回答“现在具体说什么”。
- `semantic_punctuation` 只在对应名词、关系或情绪出现时短暂进入。
- Feature 列表结束后必须出现用户情境或反问，例如“这对目标用户具体省了什么麻烦？”；答不出来的 feature 不应占据主画面。
- 图解只用于实拍难以直接表达的关系、因果或步骤，并在规格中标为说明性；有被误认为真实证据的风险时还要在画面上标注。真实产品结果仍由真实素材承担。
- 先选有连续负空间的底片，再排章节主句。人物眼睛、嘴、手、产品和证据动作优先于装饰文字。

## 真实性闸门

- “不购买的代价”只能描述已存在且不过度夸张的摩擦，不能制造安全威胁、健康恐惧、羞辱或焦虑。
- 涉及防火、防滑、治疗、过敏、儿童/老人安全、耐用年限、性能数值等主张时，必须有对应的已核验证据；生活场景图片不是证明。
- 说明性生成图必须登记来源和 `claim_boundary`；不能冒充实测、真人评价、新闻、认证、真实 UI 或 before/after。若普通观众可能把它误认为真实产品、人物、场景、结果或证据，必须同时在画面上做清楚的说明性标注；纯装饰图标、抽象纹理或明显非写实底板可只保留规格内的来源与边界记录。
- 英语与西语分别母语化受众时刻、情绪强度和 CTA，不做逐句直译；同一 feature 在不同市场可能对应不同理由。

## 审核卡

交付脚本或精剪规格前逐项回答：

1. 一句话能否说清“给谁、在什么时刻、解决哪种真实摩擦”？
2. 每个 benefit 能否回指一个 verified feature 和对应证据？
3. 场景图是在说明情境，还是被错误地当成功效证明？
4. “现在行动”是否依赖未经核验的稀缺、价格、风险或恐惧？
5. 删除产品名后，话术是否仍像任何产品都能套用？若是，桥还不具体。
6. 静音观看时，章节主句、真实证明和唯一 CTA 是否仍可理解？

这些检查只验证信息结构和证据边界，不预测留存、点击或转化。
