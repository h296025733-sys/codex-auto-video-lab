# 编辑器路由、资产许可与验证边界

目标是用现有、可审计的工具完成项目，不为“看起来高级”而堆叠依赖。先判断成片需要什么层级，再选择最小工具链。

## 路由决策

| 需求 | 首选路径 | 原因与边界 |
|---|---|---|
| 素材登记、哈希、探针、离线转写、场景/静音候选、联络表 | `auto-video-editor` 工作区 | 适合可重复分析和证据归档；场景点只是候选，仍需目视判断 |
| 硬切、裁切/缩放、基础调色、音量处理、基础烧录字幕、稳定批量导出 | FFmpeg / libass，经 `auto-video-editor` | 确定性强、便于命令审计；复杂弹簧动画、交互式网格排版成本较高 |
| 词级 kinetic typography、弹簧/bounce、持续 tier grid、产品抠图、多层遮罩、复杂 CTA 动效 | OpenChatCut / Remotion | 更适合图层、时间线和组件化 motion graphics；必须做真实导出验证，不能只看预览 |
| 真实演示 + 少量高级图层 | 混合路径 | 先在 D 盘工作区分析并生成精剪规格，再用 OpenChatCut/Remotion 合成，最后回到 FFmpeg 做探针、全片解码和代表帧检查 |
| 只有简单字幕却计划新增动画框架 | 保持现有路径 | 不新增依赖；先用现有 Remotion/FFmpeg 能力证明需求 |

### 选择规则

1. 只有硬切、基础字幕和音频处理：走 `auto-video-editor`。
2. 出现两个以上持续信息层（人物 + grid + packshot + 动态字幕等）：走 OpenChatCut/Remotion。
3. 需要批量语言版本：把文案、断句、颜色、字体、时码和资产 ID 参数化；不要复制粘贴时间线后人工漂移。
4. 需要生成图：先生成和审核独立资产，再导入时间线；生成步骤不能藏在不可复现的手工操作里。
5. 任何路径都要保存源时码、资产来源、许可证、生成提示词与实际导出日志。

## 已有工具与避免重复安装

- 工作区已具备固定版本的 FFmpeg/ffprobe、离线转写和分析能力；OpenChatCut 已包含 Remotion、浏览器端媒体处理及本地图层能力。
- 不因一次样片就重复安装另一套转写、场景检测、OpenCV、SAM/Track Anything 或大型视频增强栈。只有现有能力无法满足已定义需求、硬件足够且有维护/许可方案时才评估。
- 动画可以先用 Remotion 原生插值、spring 和 CSS 实现。只有项目确实需要导入 Lottie JSON 时，才加入与当前 Remotion **完全同版本**的 `@remotion/lottie` 及兼容 `lottie-web`，并做独立渲染测试。
- 库的 GitHub stars、下载量或“热门”只能说明采用度，不能替代安全审查、版本固定、许可证核对和本机测试。

## Remotion 许可注意事项

Remotion 不能被默认描述为 MIT 或标准 OSI 开源组件。它采用自己的许可证与商业条款，团队规模、公司用途和自动化/渲染服务场景可能触发付费要求。

- 每次用于商业流水线前，核对项目当前的 [LICENSE](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md) 与 [商业许可说明](https://www.remotion.dev/docs/license)。
- 记录实际使用版本及审查日期；不要把 GitHub star 数或公开源码等同于“免费商用”。
- 如果许可与当前组织/自动化场景不匹配，停止扩展 Remotion 路径并改用 FFmpeg/libass 或另行取得许可。

## 字体与动画资产

- 字体只从权威发行源取得，优先使用 [Google Fonts 官方仓库](https://github.com/google/fonts) 中具体提交固定的文件；保留每个字体目录里的 OFL/license 文本、提交哈希与 SHA-256。
- Google Fonts 仓库中的字体通常采用开放字体许可，但要以**具体字体文件旁的许可证**为准；不要把整仓库一句话概括成所有文件同一许可。
- 不系统级安装字体。把最小字体子集放在 D 盘技能资产目录，并在渲染命令中显式指定，避免污染系统和运行时网络下载。
- Lottie 播放器的开源许可不等于某个 Lottie 动画素材可商用。每个 JSON、插图、图标、音效和模板都要单独记录来源与授权。
- 从他人成片截图、抠产品图、提音乐或复用动画，不会因为技术上可提取就自动拥有使用权。

## 音乐、口播与版权

- 参考成片只有扁平混音时，不能可靠断言音乐标题、stem 音量或授权来源。
- “TikTok/YouTube 热门”“GitHub 可下载”“纯音乐”都不等于允许商业广告使用。
- 可接受来源包括：用户提供并确认权利的音乐、目标平台明确允许当前商业用途的音乐库、或许可证可核验且满足署名/再分发条件的曲目。
- 若无法同时确认**适配性与授权**，输出 VO-only 或静音版本。宁可没有 BGM，也不要从类似视频提取音乐后直接用于商业成片。
- TTS/配音模型、声音克隆和人物声音同样需要核对条款与授权；没有明确同意，不克隆可识别个人的声音。

## 生成图与产品真实性

- 可生成：抽象背景、章节底板、非事实性图标、情绪插画、透明装饰贴图。
- 应使用真实素材：产品外形、接口、包装、显示数值、测试结果、用户评价、前后对比、可识别人物背书。
- 若生成素材仅用于示意，应在项目元数据中标注 `illustrative: true`。任何可能影响购买判断的虚构内容都应删除或显著说明。

## 导出与验证等级

按证据准确描述完成度：

1. **源检查**：只检查了代码、规格或时间线；没有渲染。
2. **静态/隔离测试**：脚本语法、schema、单组件或少量帧通过；不代表整片成功。
3. **本地完整渲染**：目标项目实际导出完成，并记录命令、版本、耗时和输出哈希。
4. **本地端到端检查**：在完整渲染基础上，完成 ffprobe、全时长解码、音视频时长/流检查、代表帧目视、字幕安全区与音频检查。
5. **目标环境验证**：在用户实际发布/播放环境中验证。只有真正执行后才能如此表述；本地检查不能证明平台上传、转码、版权审核或转化表现。

最低交付检查：

- 输出分辨率、帧率、编码、时长和音频流符合规格。
- 完整文件从头到尾可解码，不只检查前几帧。
- 抽查 hook、每个 retention event、章节切换、CTA 和末帧。
- 英语/西语逐版本检查断句、字符覆盖、口播同步与 UI 安全区。
- 音乐、字体、图片、模板和生成素材均能追溯来源/许可。
- 未实际渲染或未在目标平台测试时，在交付说明中明确写出。
